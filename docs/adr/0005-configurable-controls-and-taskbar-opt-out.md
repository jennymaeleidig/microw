# Configurable header controls and taskbar opt-out

The window header is configurable, not fixed: `controls: { left: [...], right: [...] }` — arrays in render order over `min` / `max` / `close`, defaulting to all three on the right (`{ left: [], right: ['min', 'max', 'close'] }`). A control's `mcrw-btn-*` class is structural iff the control is enabled; disabled controls are absent from the DOM. Resize is a constructor toggle (`resizable`, default true) that adds `mcrw-no-resize` and omits the handles; the class remains a valid consumer-applied behavior gate. The taskbar is an option too: a per-window opt-out (`taskbar: false` — the window gets no taskbar item and is non-minimizable: `minimize()` is a library-level no-op, so the item's purpose is gone), plus a **library-level global disable** that removes the min control from every header, makes `minimize()` a no-op, restores any minimized windows to `normal`, and makes `MicroW.taskbar(root)` create nothing.

Headless means "no styling and no fixed chrome", not "no chrome at all": the library ships structural controls so a bare window is usable, but every piece of chrome — which buttons, whether resizing exists, whether the taskbar exists — is consumer-configurable, because each one has real per-app costs (layout space, event surface, accessibility tree). The global disable exists so an app that is fundamentally non-minimizing (a document editor, a kiosk) is not forced to thread per-window options through its own code; disabling must restore minimized windows rather than stranding them in a state with no affordance.
