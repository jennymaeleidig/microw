# State model: three mutually-exclusive states, focus orthogonal

A window has one of three mutually-exclusive states — `normal`, `min`, `max` — and one orthogonal state, **focus**. The state classes are exactly `mcrw-min` / `mcrw-max` (`normal` carries no class, since base `.mcrw` rules ARE normal styling) plus `mcrw-focused`, which tracks focus. Focusing a window raises it to the top of its root's z-order (a fresh monotonic `zTop`), so focusing is what makes a window topmost; focus and z-order are otherwise independent — a newly created window mounts on top without being focused. Focus is model state — never real DOM focus — so a minimized or maximized window can still be the focused one.

- **`minimize()`** transitions to `min` (adding `mcrw-min`, the only hiding class), leaves geometry untouched, **remembers the state it left (`normal` or `max`)**, and fires `onminimize`. If the window was focused, it blurs (`onblur`) and hands focus to the next most-recently-used **non-minimized** window (`onfocus`); if none exists, no window is focused. It is a no-op on a non-minimizable window (min control disabled), so nothing can be stranded in a state with no way back.
- **`maximize()`** fills the root's work area and remembers the pre-max geometry; `onmaximize` fires. The header's `mcrw-btn-max` control toggles `normal ↔ max` — the only in-window control that returns a `max` window to `normal`.
- **`restore()`** returns a `min` window to the state it was in before minimizing — `normal → min → restore` lands on `normal`, while `max → min → restore` lands on `max` (re-filling the work area and keeping the remembered pre-max geometry). Restoring from `max` returns to `normal`, restoring the pre-max geometry and clearing the memory. `onrestore` fires once per restore, with the window already in its restored state — consumers must not assume restore always lands on `normal`. Restore focuses the window and returns the instance.

Focus-handoff on close and minimize shares one MRU order — next most-recently-interacted non-minimized window, or nowhere — so focus never lands on a hidden window.

**Gating:** drag and `moveTo` share the same gate as resize — all are no-ops outside `normal` — so a `max` window's geometry stays owned by maximize and a `min` window's geometry stays frozen. Resize (pointer and programmatic) and drag are simply dead outside `normal`.
